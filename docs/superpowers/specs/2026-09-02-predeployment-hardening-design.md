# Science-Lab 部署前阻断项修复设计

## 目标

在不改变现有产品形态、不部署、不接触真实 API Key 的前提下，修复最后一轮审查确认的四类上线阻断问题：DeepSeek 模型兼容、内容源参数边界、PWA/目录发布一致性、Node 依赖可复现性。

## 范围

本轮采用定点加固，不拆分 `index.html`，不移除旧账号接口，不部署 Cloudflare Worker，也不改变用户已确认的“物理·高中”和“生物·高中”隐藏状态。

### 1. DeepSeek V4 兼容

- 内置服务端模型从 `deepseek-chat` 改为 `deepseek-v4-flash`。
- 服务端发往 DeepSeek 的请求固定加入 `thinking: { "type": "disabled" }`，保持中学生问答快速、直接，并避免前端忽略思考流时长时间只显示省略号。
- 前端默认模型、设置占位、部署验证命令和自动化测试同步更新。
- 前端发送历史时把每条消息裁剪为后端允许的 4000 字符；本地展示记录仍可保留现有 6000 字符上限。
- API endpoint 和 SSE `data: [DONE]` 处理保持不变。

### 2. 内容源参数边界

- 新增一个可在浏览器和 Node 测试中共用的小型内容源解析模块。
- 生产环境始终使用 `https://html.xingnian.net.cn/`；部署在内容域名本身时使用相对路径。
- 只有 `localhost` 和 `127.0.0.1` 允许使用 `?base=/.../` 根相对路径进行本地联调。
- 拒绝协议相对地址、绝对外部地址以及 `javascript:`、`data:` 等非 HTTP 内容源。
- 本轮不直接给实验 iframe 添加 `sandbox`；实验可能使用全屏、下载、传感器或其他能力，需另开真机兼容性审查后再收紧权限。

### 3. PWA 与目录发布一致性

- Service Worker 只删除旧的 `sl-shell-*` 缓存，不触碰同域其他应用缓存。
- `manifest.json` 与 `catalog-control.json` 仅在 HTTP 成功且响应类型为 JSON 时写入缓存；异常响应优先回退到最后一份有效缓存。
- 仅缓存明确列入 App 壳清单的同源 GET，不再拦截 `/api/` 或任意同源 URL。
- 缓存版本递增，新增内容源解析模块进入预缓存清单。
- nginx 不再把缺失静态资源回退成 `index.html`；缺失 JSON、JS、图标必须返回 404。
- 部署文档改为 release 目录加原子符号链接切换，避免静态文件只更新一半；回滚通过切回上一 release 完成。

目录控制仍保持当前产品语义：首次加载完全拿不到有效控制文件时默认发布内容。隐藏状态不是权限控制，强制下线仍需在内容站拒绝对应路径。

### 4. 可复现依赖

- 从 `server/api/.gitignore` 移除 `package-lock.json` 忽略规则。
- 重新生成 lock 文件，确保 `npm audit --omit=dev` 无已知生产依赖漏洞。
- 部署文档使用 `npm ci --omit=dev`，保证服务器安装与审查过的依赖树一致。

## 错误处理

- 内容源非法时静默使用官方内容站，不把不可信值拼接进 iframe。
- 网络目录配置异常时只使用最后一份验证过的缓存；无缓存时延续现有“全部发布”降级并记录警告。
- Service Worker 注册失败继续允许页面在线使用，但控制台记录有上下文的警告，不再空 catch。
- DeepSeek 上游错误、超时和断线语义保持现状。

## 测试策略

1. 先增加失败测试，覆盖生产环境拒绝恶意 `base`、本地允许根相对路径、DeepSeek V4 请求体、消息裁剪、SW 缓存前缀/响应校验和 nginx 404/原子发布文档。
2. 逐项实现最小代码并让定向测试转绿。
3. 运行完整 `npm test`、全部 JS/JSON/Python/shell 语法检查和 `npm audit --omit=dev`。
4. 用本任务专属无界面浏览器复测构造 `base` 链接，确认不能再修改父页面。
5. 不调用真实 DeepSeek；真实 Key 验证留到部署窗口，仅执行一次最小 SSE 请求。

## 不在本轮处理

- 旧账号接口与 MySQL 的结构解耦。
- 全站 AI 费用熔断、Redis 多实例限流和校园 NAT 配额模型。
- Cloudflare Worker 备用代理加固。
- AI 隐私提示、CORS 错误格式、安全响应头及 localStorage 全面封装。

这些事项保留在上线建议中，但不扩大本轮四项阻断修复的实现范围。
