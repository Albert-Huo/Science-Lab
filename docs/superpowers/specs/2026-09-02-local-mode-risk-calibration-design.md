# Science-Lab 免登录本地版表述校准与风险加固设计

## 目标

在不改变现有产品行为、接口兼容性和部署拓扑的前提下，完成两处事实校准，并把已验证但尚未固化的关键行为补入自动化测试。

1. 明确“免登录”只描述当前前端体验；`server/api/` 中的旧账号和进度接口仍为已有部署保留。
2. 明确“相关数据库代码和结构未改动”不等同于“生产数据库内容已经验证完好”；上线前必须备份并执行只读核验。

## 范围

### 文档校准

- `README.md`
  - 在“免登录本地版”中限定表述范围为当前前端。
  - 在“旧接口兼容”中说明仓库审查能确认的边界，以及生产数据需要独立验证。
- `docs/aliyun-deploy.md`
  - 增加上线前数据库备份、只读统计、旧接口验证和回滚步骤。
  - 增加风险解除清单，覆盖匿名费用滥用、共享出口 IP、单进程限流、真实上游验证、多标签页覆盖和前端回归测试。

### 自动化测试加固

- 扩展现有 `server/api/test/smoke.js`，永久覆盖：
  - 每日限流达到上限后返回 429。
  - 客户端断开后服务端中止 DeepSeek 上游请求。
- 为前端本地存储逻辑增加不依赖真实网络和真实 DeepSeek 的回归测试，覆盖：
  - 损坏的 AI 会话 JSON 自动重置。
  - 总会话数超过 200 后淘汰时间最早的记录。
  - 新写入失败时不覆盖已有持久化数据。

前端测试优先复用现有项目能力；若仓库没有浏览器测试框架，则采用最小的 Node 测试抽取方式，不引入大型依赖或新的构建系统。

## 风险解除方案

### 匿名接口费用滥用

- 本轮：文档要求使用服务端专用 Key、费用告警或余额控制，并监控 429、502 和调用量；明确 CORS 不是访问控制。
- 后续运维阶段：在 nginx/WAF 增加全局速率与并发控制；如出现分布式滥用，再评估挑战机制或匿名配额凭证。
- 验收：真实调用前确认费用控制已生效，使用服务端专用 Key 完成首次验证，并将供应商账户的可用余额或预算控制在可承受范围。

### 学校或宿舍共享出口 IP

- 保留环境变量可调阈值，不在代码中抬高默认值。
- 上线初期观察 429 比例；确认正常课堂流量被误伤后，再按实际并发调整分钟限额，同时保持每日费用边界。

### 多实例限流

- 当前单 PM2 进程继续使用内存计数。
- 启用 PM2 cluster、容器副本或多机部署前，必须切换共享 Redis store 或把全局限流上移到网关；未完成前禁止横向扩容 AI API。

### 生产数据安全

- 部署前生成带时间戳的数据库备份，并记录校验信息。
- 部署前后只读比较用户数、进度记录数和最新更新时间；不通过前不执行任何数据修复或删除。
- 后端回滚只回退应用版本和环境变量，不回滚或重建数据库结构，因为本次没有数据库迁移。

### 多标签页本地存储覆盖

- 本轮保持现状并在文档中说明边界，不引入复杂同步协议。
- 若实际反馈出现丢记录，再使用 `storage` 事件加版本号或时间戳合并；该行为变化需要独立设计和测试。

## 验证

- `npm test`：现有测试和新增测试全部通过。
- `node --check server.js test/smoke.js`：服务端脚本语法通过。
- 前端本地存储测试：损坏恢复、200 条淘汰、写入失败保护全部通过。
- `git diff --check`：无空白或补丁格式问题。
- `git status --short`：只出现本设计范围内的文档和测试文件。

## 非目标

- 本轮不部署 Redis，不修改 nginx/WAF，不接触生产数据库，不调用真实 DeepSeek。
- 不改变旧账号接口、不删除 MySQL 结构、不修改现有前端交互。
- 不自动创建提交或 push；完成后由用户决定如何提交和发布。
