# 无身份产品统计与安全流量隔离设计

## 背景与目标

现有私有流量后台主要从 Nginx 与 AI 专用日志观察原始请求、入口特征、自动化流量和服务状态，适合安全与运维判断，不适合回答“网站哪些功能被使用”。其中基于 IP 与 User-Agent 的组合只能作为技术流量估算，不能称为 UV、真人或真实用户。

本设计增加一套默认开启的无身份产品统计，只回答页面、实验、操作和接口被使用多少次；它从采集开始就不建立访客身份，不依赖 Cookie、浏览器指纹、IP 哈希或跨页面事件序列。同时保留现有安全日志用于防攻击、排障和必要的网络安全记录，但禁止将其回流到产品统计计算 UV、画像或访问路径。

目标如下：

- 默认获得页面 PV、实验打开、完成事件、关键交互、来源类别及 API 使用量。
- 统计链路不生成或派生能够持续区分浏览器的标识。
- 安全日志与产品统计在数据源、权限、存储、代码和页面语义上隔离。
- 后台明确显示 UV 与会话数“未采集”，不把独立 IP 或未分类流量包装成真人。
- 不购买云服务，复用当前 ECS 计算资源，但不复用 AI 配额 Redis 的数据实例。
- 为未来经明确同意的短期会话分析保留设计位置，生产环境保持关闭。

非目标：本期不识别具体用户，不做广告归因、跨站追踪、AB 测试、热力图、鼠标轨迹、键盘内容、用户画像或个性化推荐，也不启用第二层会话统计。

## 总体架构

两条数据链路分别处理，不互相查询或关联：

```text
普通网页/API 请求
        ↓
安全与运行日志
必要 IP、UA、请求状态等
        ├─ 防攻击与异常检测
        ├─ 故障排查
        ├─ 独立权限和保存周期
        └─ 禁止用于 UV、画像或用户路径

浏览器匿名事件 / 服务端 API 计数
        ↓
严格白名单校验
        ↓
直接增加小时与每日聚合计数
        ↓
私有后台的网站使用概览
```

安全日志继续位于受限日志目录，由现有流量任务读取。产品统计写入独立聚合存储和命名空间，统计服务身份无权读取普通 Nginx 日志；流量报表也不读取产品统计之外的浏览器状态。前端页面只消费服务端生成的汇总结果，不能在浏览器中拼接两个数据源。

同一台 ECS 上新增独立、仅监听回环地址且有资源上限的本地 Redis 聚合实例，不购买云 Redis。实例使用独立系统服务、账号、密码、数据目录和持久化文件，设置有限数据内存、服务总内存保护、`noeviction` 与 AOF every-second；具体上限在部署前按生产余量验证，不能挤占公开站点和 AI 服务。不得复用 `science-lab-quota-redis`：该实例承担 AI 全站额度与并发保护，统计写入不能与额度控制争抢内存或影响额度可用性。端口只在确认生产未占用后选定，不在设计阶段假定固定值。

## 第一层：默认无身份聚合统计

### 浏览器事件

浏览器只允许提交版本化的固定结构：

```json
{
  "v": 1,
  "event": "experiment_open",
  "experiment_id": "free_fall"
}
```

首版事件类型与字段为：

| 事件 | 必需维度 | 可选维度 | 含义 |
| --- | --- | --- | --- |
| `page_view` | `page_id` | `source` | JavaScript 成功执行后的页面打开 |
| `experiment_open` | `experiment_id` | 无 | 实验内容实际打开 |
| `key_action` | `page_id`、`action_id` | 无 | 明确列入白名单的开始、重置、模式切换等操作 |
| `experiment_complete` | `experiment_id` | 无 | 仅在内容端未来提供统一、明确、白名单完成信号后启用；首版不接受也不发送 |

`page_id`、`experiment_id` 与 `action_id` 必须来自发布清单或代码内固定枚举。禁止自由文本、按钮文案、CSS 选择器、页面标题、鼠标坐标、滚动位置、按键内容和任意属性透传。单次请求体采用小尺寸上限，出现未知字段、未知 ID、错误类型、嵌套对象、数组或超长值时整体拒绝。

来源只在浏览器端将 `document.referrer` 归类为 `direct`、`internal`、`search` 或 `external`；不上传完整 Referer、域名、路径或查询参数。服务端以接收时间生成小时和日期桶，不接收客户端时间、时区或持久 ID。

匿名层明确禁止：

- `visitor_id`、`session_id`、Cookie ID 或 localStorage ID；
- Canvas、字体、WebGL、音频、设备参数组合等浏览器指纹；
- IP、完整 UA、完整 Referer、URL query、请求正文内容或聊天内容进入统计存储；
- IP 哈希、IP + UA 哈希、日期盐哈希或其他派生唯一标识；
- 原始事件行、事件序列、跨页面身份关联或跨日追踪；
- 用安全日志补算 UV、漏斗、路径或用户画像。

页面卸载时不建立 localStorage/IndexedDB 重试队列。发送失败可以丢失计数，不能为了提高统计完整性在设备上留下待发送行为历史。

### 统计接口与 Nginx 边界

匿名事件接口只接受同源 HTTPS `POST` 和 `application/json`，拒绝 query 参数、重定向、跨域凭据及非白名单结构。`Origin`/`Sec-Fetch-Site` 只在请求处理期间用于降低跨站伪造，不进入统计存储或逐事件日志，也不能据此声称事件一定来自真人。接口响应固定且不设置 Cookie。

该 location 使用不含 `$remote_addr`、UA、Referer、Cookie、请求 URI/query 和请求体的专用最小日志格式，或在具备等价运维可观测性的情况下关闭逐请求访问日志。允许记录固定端点、服务端时间桶、HTTP 状态类别、请求长度区间和耗时区间；这些记录不得含事件维度，产品计数直接写入聚合存储。

Nginx 可以在内存中使用来源地址执行每 IP 短时限速，以保护公开端点，但不得把该地址写入产品统计或统计接口日志。429 只进入安全/运行状态计数。接口还设全局速率、请求体和并发上限，避免匿名端点成为资源消耗入口。

### 直接聚合与保留

校验通过后立即对固定维度执行原子增量，不保存原始事件。例如：

```text
analytics:v1:hour:2026-09-21T10:page_view:home
analytics:v1:day:2026-09-21:experiment_open:free_fall
analytics:v1:day:2026-09-21:key_action:home:start
```

真实键结构可以使用 Hash 压缩，但必须保持同样的有限维度。维度基数由清单限制，计数使用非负安全整数并防止溢出。小时桶满足 24 小时后台趋势，每日聚合最多保留 400 天，与现有私有后台历史窗口一致；过期后自动删除。因为存储内容只有固定维度的汇总计数，导出文件同样不得包含原始事件或身份数据。

统计存储失败不阻断页面或实验使用。服务端记录固定错误代码和聚合失败次数，不记录请求体；浏览器不无限重试。后台在缺少完整观测时显示“未采集”“部分采集”或“数据延迟”，不能把缺失显示为 0。

### API 使用统计

API 指标在服务端按固定路由名称、状态码类别和耗时区间直接累计：

- 路由只用枚举名称，如 `health`、`ai_chat`，不保存原路径、query 或参数；
- 状态只统计 `2xx`、`4xx`、`429`、预期停用 `503`、其他 `5xx` 等既有类别；
- 耗时只进入固定区间，不保存单请求时间线；
- 不统计请求正文、提示词、回答、供应商密钥或用户提供的内容；
- AI 专用匿名运行日志仍按现有设计工作，但不得被用于推断访客身份。

## 安全日志与产品统计隔离

隔离不是只靠页面文案，必须落实为以下约束：

- **数据源隔离**：安全流量来自受限 Nginx/AI 日志；产品统计来自匿名事件与服务端聚合计数。
- **存储隔离**：安全日志文件与产品聚合存储分别设置目录、账号、权限、备份和保存周期。
- **读取隔离**：产品统计服务无权读取普通访问日志；报表合并代码不得按 IP、UA、Cookie 或时间关联两边记录。
- **代码隔离**：事件校验与聚合使用独立模块；现有自动化分类器不作为产品事件处理器。
- **展示隔离**：后台先展示“网站使用概览”，再展示标明安全口径的“安全流量”；两个区域不共享“用户”“真人”“UV”等名称。
- **导出隔离**：产品 CSV 只有固定维度和计数；安全 CSV 延续现有只导出汇总、不导出 IP、UA、原始路径和请求正文的规则。
- **权限隔离**：两个区域继续受后台 Basic Auth 保护；公开站点不提供统计查询接口。

现行《网络安全法》要求网络运营者按规定留存相关网络日志不少于六个月，但“相关网络日志”不应未经评估就解释为完整保留全部 Nginx 原始访问行。当前约十天日志策略需单独进行主体适用、等保要求、必要字段、权限和期限评估。本项目不以产品统计改造为由扩大 IP、UA 的保存范围，也不宣称仅凭本设计已经满足全部法律义务。

## 后台信息架构与指标口径

### 网站使用概览

首屏使用独立卡片和趋势图展示：

- 页面浏览 PV：有效 `page_view` 事件数；刷新会再次计数，无 JavaScript 的访问不会计入。
- 实验打开：有效 `experiment_open` 事件数。
- 实验完成事件：有效 `experiment_complete` 事件数，不称完成率。
- 关键交互：白名单 `key_action` 事件总数及固定操作分布。
- API 调用：服务端固定路由计数。
- UV：`未采集`。
- 会话数：`未采集`。

图表包括小时/每日趋势、热门实验、来源类别、关键操作分布和 API 状态/耗时。所有区域固定提示：“匿名事件计数可能包含自动化访问，不代表独立人数。”历史图标注采集开始时间和覆盖状态。

### 安全流量

现有原始请求与自动化分类保留在单独区域：

- HTTP 原始请求；
- 来源 IP 组合数量仅在确有安全分析价值时展示，并明确为安全口径、不是 UV；
- 已验证搜索引擎爬虫；
- 声明身份的 AI Bot；
- 扫描器或敏感路径探测；
- 自动化工具或监控；
- 未分类请求；
- 4xx、429、预期停用 503 与其他 5xx。

自动化身份和风险行为继续分开。“AI Bot”表示声明或验证的自动化身份，不自动等于攻击；“未分类”表示证据不足，不等于真人。原 `visitorEstimate` 如继续保留，必须改为技术性的“IP + UA 组合估算”并位于安全区域，不参与任何产品指标。

### 数据与隐私状态

后台增加可核验状态卡：

```text
产品统计方式       无身份聚合
统计 Cookie        未设置
浏览器指纹         未使用
跨页面身份关联     未使用
跨日追踪           未使用
UV                 未采集
会话分析           未启用
第二层统计         已设计 / 生产关闭
统计开始时间       服务端时间
最后成功聚合       服务端时间
统计规则版本       analytics-v1
```

原始请求量与产品 PV 不放在同一组卡片中直接比较。不存在会话分母时不显示实验完成率；数据故障显示不可用而不是零。

现有跨域实验页没有统一、可信的完成信号。首版“实验完成事件”显示“未接入”，不使用滚动到底、停留时长、页面离开或打开历史进行推断，也不把未接入显示成 0。未来只有内容端按独立设计发送明确白名单信号后，才启用 `experiment_complete`。

## 隐私说明与用户体验

第一层不设置统计 Cookie，因此不显示统计同意弹窗。网站页脚提供简洁、容易访问的《隐私说明》，至少说明：

> 为了解网站整体使用情况，我们统计页面访问次数、实验打开次数和部分功能点击次数等无身份汇总数据。该统计不设置统计 Cookie，不创建访客唯一标识，不进行浏览器指纹识别，也不使用 IP 地址建立用户访问轨迹。网站运行和安全防护产生的必要服务器日志与产品统计分别处理，不用于用户画像。

完整说明应分别列出产品统计与安全日志的目的、数据类型、保存期限、保护措施和联系渠道，避免把两类处理笼统写成“匿名统计”。页面不得使用默认勾选、“继续使用即同意”或反复弹窗。

## 第二层：经同意的短期会话统计

第二层只完成技术设计和禁用保护，本期不启用、不设置 Cookie，也不显示同意弹窗。生产配置采用默认关闭且缺省关闭的功能开关；测试必须证明开关缺失、错误或读取失败时仍不下发标识。

未来确有产品决策价值并解决未成年人同意问题后，候选设计为：

- 在充分告知并由合适用户主动同意后，设置服务端生成的 128 位随机 Cookie；
- Cookie 为 `Secure`、`HttpOnly`、`SameSite=Lax`，最长 24 小时，不跨站使用；
- 会话按短期空闲窗口划分，状态进入独立命名空间并在约 24 小时后自动删除；
- 只关联同意范围内的页面、实验、停留区间和白名单操作，不采集输入内容或精细轨迹；
- 支持撤回并立即删除相应短期状态；拒绝后只保存不具追踪用途的本地偏好，避免频繁征求；
- 长期只保留无法回溯到会话的汇总结果。

由于科普实验站不能可靠排除不满 14 周岁用户，第二层在建立监护人同意机制、专门处理规则、撤回/删除流程和必要性评估之前不得启用。普通用户同意不能替代监护人同意。

## 滥用、失败与数据质量

无身份统计无法去重，也无法证明事件来自真人，因此不应以高成本方式尝试隐藏这一限制。保护和质量策略如下：

- 同源校验、固定枚举、有限请求体、Nginx 短时限速及服务端全局限流；
- 清单外 ID、自由文本和额外字段全部拒绝，避免存储注入和基数膨胀；
- 计数可能被脚本重复触发，页面明确标注可能包含自动化访问；
- 不以“必须识别真人”为理由引入指纹、挑战或持久标识；
- 统计写入失败不影响核心实验，使用覆盖状态反映缺失；
- 聚合存储达到资源上限时保护 AI 与公开站点可用性，停止或降级统计而不是驱逐额度数据；
- 所有生成报表采用原子替换，失败时保留上一份有效结果并标记陈旧时间。

## 测试与验收

实现阶段遵循测试先行，至少覆盖：

1. 严格 schema：正常事件通过；未知字段、自由文本、未知 ID、query、超长值和错误内容类型失败。
2. 隐私边界：浏览器不读写统计 Cookie/localStorage/IndexedDB；请求不包含完整 Referer、UA、时间、路径或派生 ID。
3. Nginx 配置：统计 location 的日志格式不含 IP、UA、Referer、Cookie、query 或请求体；限速仍有效。
4. 聚合存储：只有允许的小时/每日维度和计数，没有原始事件、身份标识或无限基数键；TTL 正确。
5. 服务端 API：只按固定路由、状态类别和耗时区间累计，不保存参数和内容。
6. 故障语义：存储中断不影响实验；缺失显示未采集/部分采集；旧快照不被坏数据覆盖。
7. 第二层关闭：默认配置、缺失配置和错误配置均不设置 Cookie，也不上传会话行为。
8. 后台语义：UV/会话显示未采集；未分类不称真人；来源 IP 不称 UV；CSV 与页面口径一致。
9. 浏览器验证：使用隔离无头环境检查桌面与手机布局、趋势切换、隐私入口及无 Cookie 行为。
10. 生产影子验证：先在隔离存储处理合成事件，确认资源上限、权限和报表，再开启公开计数；不调用收费模型。

## 发布、回滚与完成标准

发布按“存储与聚合服务 → Nginx 精确路由 → 静态埋点 → 私有后台”的顺序准备，但只有全部组件验证通过后才统一启用。激活前记录服务端采集开始时间，旧历史保持“未采集”，不得补零。部署前备份配置和私有统计状态，运行 Nginx、systemd、Node 测试及只读生产基线检查；激活后验证公开页面、实验、AI 健康与额度未受影响。

回滚关闭匿名事件入口和静态发送代码，恢复上一版 Nginx/服务/后台文件；保留已经生成的无身份聚合计数供审计，不删除或覆盖既有安全日志。任何失败优先恢复公开站点和 AI 配额服务。

完成标准：

- 产品统计全链路不存在访客或会话标识、完整网络标识和原始事件序列；
- 安全日志与产品统计不能通过代码、权限或报表进行身份关联；
- 私有后台准确展示匿名产品计数、安全流量和采集状态三类信息；
- UV、会话数和完成率没有被估算或伪造；
- 第二层在生产中可证明处于关闭状态；
- 全部自动化测试、隔离浏览器验收和生产配置验证通过；
- 不新增付费服务，不影响现有 AI 额度、并发与供应商费用控制。
