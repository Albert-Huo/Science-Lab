# 全量初中物理滚动接收器设计

日期：2026-09-04

## 目标

让 `physics-middle/` 下当前全部 70 个初中物理实验都能响应实验馆右侧内容滚动手柄。现有宿主、手柄视觉、切换按钮和实验自身交互保持不变。

## 已确认边界

- 不识别或适配实验内部滚动容器；所有页面统一使用 `document.scrollingElement`。
- 不逐页判断内容是否超过一屏，直接为全部 70 个实验接入接收器。
- 宿主已有的状态规则保持不变：接收器会上报根页面滚动范围，宿主根据上报状态决定手柄可用状态。
- 不修改实验器材、教学流程、布局、面板或物理逻辑。

## 接入方式

在内容仓库根目录新增不可变版本文件：

```text
experiment-scroll-receiver.v1.js
```

其内容与 Science-Lab 仓库的 `experiment-scroll-receiver.js` 逐字一致。每个初中物理实验在 `</body>` 前只保留一个引用：

```html
<script src="../experiment-scroll-receiver.v1.js" data-science-lab-scroll></script>
```

相对路径同时兼容自定义域名 `html.xingnian.net.cn` 和 GitHub Pages 的 `/HTML-/` 项目路径。实验 1、35、41 现有的内联试点代码改为同一外部引用；其余实验只增加该引用。

采用版本化文件名而不是可变文件加缓存参数：后续接收器变更发布 `v2`，避免旧 CDN 或浏览器缓存与新实验 HTML 不一致。

## 安全与独立运行

- 接收器只接受父窗口来源为 `https://lab.xingnian.net.cn` 的会话；本机联调仅允许 loopback 到 loopback。
- 校验消息来源窗口、来源域、会话标识、命令类型和滚动数值边界。
- 实验独立打开时 `parent === window`，接收器不建立连接，也不改变页面行为。
- 不添加统计、遥测、存储、API 或其他网络请求。

## 可重复发布工具

更新 Science-Lab 的 `tools/check-scroll-release.mjs`，从“仅验证 1、35、41 的内联代码”改为验证：

- `physics-middle/` 恰有 70 个目标实验 HTML；
- 每个目标文件恰有一个版本化外部引用；
- 不残留内联滚动接收器；
- 内容仓库共享接收器与 App 仓库规范源逐字一致；
- 去除新外部引用及三个旧内联块后，实验源文件与发布基线逐字一致。

增加自动化测试覆盖正常全量接入、缺失引用、重复引用、共享文件漂移及夹带实验改动。

## 验证与发布

- 先在从 `origin/main` 建立的隔离内容工作树中做机械批量改写，不使用或覆盖其他工作树状态。
- 运行全量源码验证，确保只新增共享文件并改变 70 个实验的接收器接入块。
- 使用移动端 Android 微信环境抽样验证共享脚本加载、父子页握手、右侧手柄滚动、实验切换和器材点击；不执行内部滚动区或逐页溢出审计。
- 先推送 HTML 内容仓库 `main`，等待 GitHub Pages 对应提交发布成功及现有精确 URL CDN 刷新完成。
- 公网验证共享脚本和 70 个 HTML 均为新版本，再通过 `lab.xingnian.net.cn` 抽样验证。
- Science-Lab 宿主静态代码无需改变，因此不重复发布相同的 ECS release；本次部署目标是 `html.xingnian.net.cn` 内容站。Science-Lab 中的验证工具和文档正常提交、推送到 `main`。

## 回滚

若内容站验证失败，撤销 HTML 内容仓库的全量接入提交并等待 Pages 发布完成；Science-Lab 宿主继续兼容已发布的三个旧试点接收器，不修改 API、nginx、数据库或 ECS 静态链接。
